# Asterisk application and function catalog

Use this reference when selecting a dialplan application or function for a new call flow. Confirm availability with the target release and loaded modules.

## Version

Catalog scope is Asterisk 16 through 23. Names and option semantics can vary by version and distribution.

## Security

Treat dialplan expressions, shell commands, file paths, URLs, and caller-provided digits as untrusted input. Use allowlists and never expose secrets in channel variables or verbose output.

## Selection map

| Need | Common choice | Verification concern |
|---|---|---|
| connect legs | Dial | answer, timeout, cause, bridge/media |
| move a live channel | Redirect | channel ownership and terminal event |
| explicit bridge | Bridge or ARI bridge | actual media channels and cleanup |
| queue routing | Queue | member state, timeout, queue log/events |
| IVR input | Background/Read/WaitExten | digit timeout and invalid input |
| playback | Playback/ControlPlayback | file format, interruptibility, completion |
| recording | MixMonitor/Monitor | final file availability and retention |
| conference | ConfBridge | profile, moderator, participant cleanup |
| parking | Park/ParkedCall | parking lot and timeout behavior |
| external logic | AGI/FastAGI/ARI | cancellation and channel hangup |
| media service | AudioSocket/ExternalMedia | codec, framing, RTP and backpressure |
| state | Set/SetGlobal/DB/ODBC | scope, persistence, race and injection |

## Function groups

Before using a function, resolve whether it is read-only or mutating and whether its value is channel-scoped, global, database-backed, or generated by the channel driver. Pay special attention to CHANNEL, PJSIP_HEADER, PJSIP_ENDPOINT, UNIQUEID, LINKEDID, BRIDGEPEER, CDR, and DB/ODBC functions.

## Failure contract

Every application call needs a failure path. Define behavior for invalid destination, unavailable endpoint, timeout, busy, congestion, caller hangup, missing sound file, unavailable database, and downstream service timeout. Do not infer success from dialplan continuation alone; inspect HANGUPCAUSE, application return variables, AMI events, or ARI events as applicable.

## Primary References

Official Asterisk application and dialplan function documentation is authoritative; distribution-generated dialplan is not a protocol authority.

## Verification

Use a minimal dialplan fixture and a controlled call to verify the selected application, option order, return variables, event sequence, audio path, and hangup cleanup.
